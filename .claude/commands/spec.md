`docs/01_customer.md`（3行＋🔮の仮説）を読んで、**`docs/03_spec.md` に要件定義書を書いてください。**

## この要件定義書のゴール

**「その人の業務が、この画面だけで1周回る」**ツールを1つ定義します。
説明ページ（LP）ではありません。**触ると動くツール**です。

## 絶対に守る制約

| 制約 | 理由 |
|---|---|
| **画面は1つだけ** | 25分で作り切るため。タブ切り替えも作らない |
| **操作は3つまで**（例: 追加する／完了にする／消す） | 4つ目から急に複雑になる |
| **データは `localStorage` に保存** | サーバー・DB・ログインなしで、リロードしても消えない状態を作れる |
| **ログイン・課金・メール送信は作らない** | 25分に入らない。第3回で扱う |
| **新しいライブラリを追加しない** | テンプレートの構成のまま作る |

```markdown
## 1. このツールが解くこと
（1行。「〜が分かる」「〜が減る」で書く）

- 開いて最初にしたいこと:

## 3. 画面（1つだけ）
上から順に、何が表示されるか。

1.
2.
3.

## 4. データ項目
| 項目 | 型 | 必須 | 例 |
|---|---|---|---|

## 5. 操作（3つまで）
| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | | |
| 2 | | |
| 3 | | |

## 6. やらないこと
（`CLAUDE.md` 3章の内容＋今回の範囲外を3つ以上）

## 7. 完成条件
見れば誰でもYes/Noを判定できる形で3つ。

- [ ]
- [ ]
- [ ]

## 8. 保存方法
`localStorage` に1つのキーで保存する。キー名: `xxx-data`
※ 端末ごとの保存です。複数人での共有は第3回で扱います。

## 9. ダミーデータ
初回表示で寂しくないよう、サンプルを3件入れる。
（実在の人名・連絡先は使わない）
```

## 進め方

1. 顧客仮説から**もっともらしく埋める**。空欄で止めない
2. 🔮 が付いていた仮説に依存する項目には、**同じく 🔮 を付ける**
3. 迷ったら**機能を減らす**方向で決める
4. 書き終えたら、次の1文だけ伝える

> 「要件定義書ができました。このまま `/build` で実装できます。作りますか？」

**この段階ではコードを1行も書かないでください。**
